# WB-токены VELA — матрица раз и навсегда

Зафиксировано 28.05.2026. Если меняешь — обновляй этот файл, а не код.

## 3 токена, которые надо создать в WB-кабинете

| № | Имя токена | Scope (галочки) | Права |
|---|---|---|---|
| 1 | `VELA-Read` | Статистика, Аналитика, Финансы | **только чтение** |
| 2 | `VELA-Ads` | Продвижение | чтение + редактирование |
| 3 | `VELA-Manage` | Контент, Вопросы и отзывы, Цены и скидки, Поставки, Маркетплейс | чтение + редактирование |

После создания — каждый в отдельную заметку в Apple Notes с именем `VELA-Read`, `VELA-Ads`, `VELA-Manage`. В заметке кроме токена — список scope, который реально поставила.

## Переменные в `backend/.env`

```
WB_TOKEN_READ=<токен 1>
WB_TOKEN_ADS=<токен 2>
WB_TOKEN_MANAGE=<токен 3>
```

## Почему так, а не иначе

1. **Токен на агента — НЕТ.** Один агент дёргает разные host'ы (Лео смотрит и Статистику для ДРР, и Продвижение для ставок). Маппинг по агенту сломается.
2. **Маппинг по host — ДА.** Один host = один scope = один токен. Чёткое соответствие, никакой путаницы.
3. **`VELA-Read` отдельный read-only** — потому что он дёргается чаще всех (каждые 5 минут дайджест). Если утечёт — ничего не сломается.
4. **`VELA-Ads` изолирован** — Продвижение это деньги, отдельный токен снижает blast radius при утечке.
5. **`VELA-Manage` объединяет 5 scope** — потому что это всё «управление товаром» и эти scope часто нужны в одной операции (поменять цену + написать ответ на отзыв в одной задаче).

## Что НЕ покрывают эти 3 токена

- Возвраты покупателями
- Документы
- Календарь акций
- Чат с покупателями

Если они понадобятся — добавляем в `VELA-Manage` (одной галочкой в WB, токен пересоздавать не надо если только что создали).
