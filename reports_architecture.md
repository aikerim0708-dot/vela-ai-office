# Архитектура авто-отчётов VELA Office

Цель: твой Cowork Live Artifact «Vela Daily» должен генериться автоматически каждое утро командой агентов внутри VELA Office. Без твоего ручного запроса в Cowork.

---

## 3 типа отчётов

| Отчёт | Когда | Кто запускает | Кому идёт |
|---|---|---|---|
| **Daily** | 07:00 каждый день | systemd timer на VDS | Telegram чат (короткий TL;DR) + Mini App (полный) |
| **Weekly** | Воскресенье 21:00 | systemd timer | Telegram + Mini App |
| **Monthly Finance** | Последний день месяца 23:00 | systemd timer | Telegram + Mini App |

---

## Кто что генерит

Каждый агент пишет свою секцию. Макс сводит.

| Секция отчёта | Агент | Источник данных |
|---|---|---|
| Верхний KPI (прибыль, заказы, затраты, ДРР) | **Макс** | сводит от Лео + Зары |
| Бритва: РК по зонам | **Лео** | `/adv/v3/fullstats?ids=29230612` |
| Ресницы: РК по зонам | **Лео** | `/adv/v3/fullstats?ids=32284868` |
| Всего по товару (реклама + органика) | **Лео + Зара** | sales + fullstats + юнитка |
| Кластеры | **Лео** | fullstats детальные |
| Воронка CTR | **Лео** | расчёт из fullstats |
| Аномалии | **Макс** | сравнение с baselines в Brain |
| Прорывы | **Лео + Макс** | сравнение с прошлым |
| Рекомендации на завтра | **Лео + Макс** | приоритизация |
| Портрет покупателя | **Анна** | seller-analytics-api (или ручной upload если WB защищает) |
| Остатки и поставки | **Анна** | stocks API |
| Финансовый P&L | **Зара** | reportDetailByPeriod + cost-structure |
| Юнит-экономика | **Зара** | sales + cost-structure |
| Маркетинговые гипотезы | **Ева** | Brain (hypotheses) |

## Алгоритм генерации Daily (07:00)

```
1. systemd timer → scripts/generate_daily_report.py
2. Скрипт собирает контекст:
   a. данные WB (через wb_client.py) за вчера
   b. вчерашний отчёт (для сравнения)
   c. Brain VELA (baselines, гипотезы, события)
3. orchestrate_goal("сгенерировать Vela Daily за <дата>"):
   a. Макс делегирует параллельно: Лео, Анна, Зара
   b. Каждый возвращает свою секцию в Markdown по шаблону
   c. Макс собирает в единый отчёт
4. Сохранение:
   a. data/reports/2026-05-28-daily.md (полный markdown)
   b. data/reports/2026-05-28-daily.json (структурированные данные для UI)
5. Публикация:
   a. Макс отправляет в Telegram чат: TL;DR (5-7 строк) + ссылка
   b. Полный отчёт доступен в Mini App: /reports/2026-05-28
   c. Запись в Brain как событие "daily report generated"
```

## API endpoints

| Endpoint | Метод | Что делает |
|---|---|---|
| `GET /api/reports` | GET | Список всех отчётов (метаданные) |
| `GET /api/reports/{type}/{date}` | GET | Конкретный отчёт (Markdown + JSON) |
| `POST /api/reports/generate/{type}` | POST | Триггер генерации вручную (кнопка «Обновить») |
| `POST /api/reports/{id}/share/telegram` | POST | Шарит отчёт в указанный chat_id |
| `GET /api/reports/{id}/export/pdf` | GET | Экспорт в PDF (через wkhtmltopdf) |

## Где взять данные которых нет в WB API

Некоторые блоки требуют данных не доступных через стандартный API:

| Блок | Источник | Как получить |
|---|---|---|
| Портрет покупателя (по зонам) | seller.wildberries.ru/platform-analytics | Через Claude in Chrome скрейпит (т.к. WB защищает от headless), либо вручную upload скриншот → парсим |

| Баланс производства / FBW в пути | вручную upload | Зара читает из `docs/anna-context/incoming-supplies.md` |
| Конкуренты | Knowledge Inbox | Из Inbox, классифицирует Макс |

## Что меняется по сравнению с Cowork Live Artifact

| Параметр | Cowork | VELA Office |
|---|---|---|
| Триггер | твой запрос в Cowork-сессии | cron 07:00 автоматически |
| Источник анализа | один Claude в Cowork | команда из 5 агентов с разделением ролей |
| Скорость | 30-90 сек на запрос | генерится ночью, утром уже готов |
| Доступ | только тебе в Cowork | через Telegram + Mini App (с телефона) |
| Хранение | в одной сессии | архив всех отчётов в `data/reports/` |
| Стоимость | $0.15-0.30 за запрос | то же, но автоматизировано |
| Шаринг | копировать вручную | кнопка «Поделиться в Telegram» |
| Связь между днями | ты сама помнишь | агенты сравнивают с прошлым автоматически |
