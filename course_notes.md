## Урок 2 (Модуль 2): Кастомизация агента в копирайтера

**Тип:** Теория · 35 мин · ✅ пройден

**Что автор делает:**

1. **Создаёт copywriter SKILL.md** — отдельный навык на путь `/skills/creative/copywriter/`. Описывает что агент умеет писать (заголовки, лендинги, посты, гайды, email-цепочки, офферы).

2. **Создаёт папку контекста** `docs/copywriting/`:

   - `swipe-file.md` — удачные структуры/хуки/офферы
   - `headline-examples.md` — сильные заголовки
   - `banned-phrases.md` — запрещённые фразы

**Главная мысль:** агент не «магически учится». Качество растёт когда у него постоянный контекст: примеры, правила, ограничения, образцы.

  - `voice-guide.md` — стиль VELA (премиум, эстетика, минимализм)
  - `good-texts.md` — лучшие описания твоих карточек (бритва, ресницы)
  - `swipe-file.md` — хорошие тексты конкурентов на WB
  - `headline-examples.md` — заголовки которые сработали (CR↑)

ROI: точная маржа от роста CR карточки. Каждые +1% CR на бритвах ≈ дополнительная выручка.

**Тип:** Теория · 16 мин · ✅ пройден

**5 артефактов автора:**

| Скрипт | Что | Когда |
|---|---|---|
| `pre-codex-sync.sh` | проверка чистоты → pull → подтянуть с VPS → secrets check → commit+push | вручную перед работой |
| `sync-from-vds.sh --prework` | быстрая синхра документов | по требованию |
| `sync-from-vds.sh --full` | снимок Hermes: workspace + статус + sanitized-конфиг + healthcheck | бэкап |
| `nightly-sync-to-github.sh` | git pull → workspace sync → secrets check → commit → push | ночью через systemd timer |

**Главная мысль:** инфраструктура вокруг агента важнее промптов. Где файлы, как версионируются, как защищены секреты, как восстановить контекст.

**В VELA (когда поднимем VDS):**

| Что | Применять? | Зачем |
|---|---|---|
| Deploy key | ✅ обязательно | иначе личный GitHub-токен на VDS = утечка = доступ ко всем репам |
| verify-no-secrets.sh | ✅ обязательно | защита `WB_TOKEN_*`, `ANTHROPIC_API_KEY` от попадания в публичный репо |
| nightly sync VDS→GitHub | ✅ полезно | полная история действий агентов |
| pre-codex-sync | ❌ пропустить | у нас не Codex |
| sync-from-vds --full | ⚠️ опционально | хватит git pull |

## Урок 4 (Модуль 2): Архитектура для агента ресерчера

**Тип:** Практика · 15 мин

**Проблема универсального ассистента:** один агент переключается между ролями (менеджер → копирайтер → ресерчер → редактор). Для ресерча это плохо.

**Хороший ресерчер должен:**
- искать несколько источников, не один
- отличать факты от мнений
- показывать на чём основаны выводы
- фиксировать спорные места
- не выдумывать цифры и названия
- отдавать структурированный brief

**Структура research brief:**
```
Aim | Confidence | Sources

## Source Notes

## Contradictions / Uncertainties

## Copywriter Handoff
```

**Финальная схема:**
```
Telegram user
  | обычные задачи          | research-задача напрямую
  v                          v
Personal Assistant Bot       Researcher Telegram Bot
  | если research            v
  v                          Research Brief + saved markdown
Researcher Profile
  | сохраняет brief
  v
/workspace/docs/research/briefs/
  | если нужен текст
  v
Copywriter Skill
  v
Final answer
```

**Главная мысль:** не задавай вопрос «сколько агентов нужно». Задавай вопрос «какая работа должна выполняться стабильно и в каком формате должен возвращаться результат».

**ПРИМЕНЕНИЕ К VELA — структурированный brief:**

Каждый агент VELA должен возвращать НЕ просто текст, а структуру с обоснованием:

- **Анна** → brief по остаткам: `aim=прогноз OOS бритвы, confidence=high, sources=[wb_stocks_api_28.05], days_to_oos=12, reorder_qty=200, contradictions=[]`
- **Зара** → brief по марже: `aim=маржа за май, confidence=high, sources=[wb_sales+wb_finance], gross=320k, net=275k, items=…`
- **Лео** → brief по кампаниям: `aim=ставки бритвы, confidence=med, sources=[fullstats_27.05], clusters_to_pause=[X,Y], reasons=…`
- **Ева** → brief по карточкам: `aim=новая шапка ресниц, confidence=med, sources=[топ-5 конкурентов + voice-guide], headline_options=[…], cta_options=[…]`

Это формат с источниками = прозрачность откуда вывод. Можно ревьюить, не делая на ощущениях.

## Урок 5 (Модуль 2): Реализация агента ресерчера

**Тип:** Теория · 20 мин

**Главный сюрприз:** отдельный profile ≠ отдельная роль. Спросил «что ты умеешь?» — ресерчер начал перечислять всё что и обычный ассистент (планы, тексты, напоминания), хотя в инструкциях написано «ты только ресёрчер».

**Три причины:**
1. Промпт сам по себе не превращает агента в специалиста
2. Старая Telegram-сессия держит старый контекст
3. Tools (инструменты) не ограничены — агент технически может всё

**Что автор сделал:**

1. **Усилил SOUL.md:** «researcher не личный ассистент, не copywriter, не coding assistant, не task manager. Занимается только web/YouTube research, fact-checking, evidence tables, briefs.»

2. **Очистил memories** профиля до минимальных research-only.

3. **Отключил tools:** `code_execution, todo, memory, session_search, delegation, cronjob, messaging, image_gen, tts, vision`. Оставил: `web, browser, terminal, file, skills, clarify`.

4. **Убил старую сессию:**
   ```
   hermes -p researcher sessions delete --yes <session_id>
   systemctl restart hermes-gateway-researcher.service
   ```

5. **Тесты:**
   - «Что ты умеешь?» → только research-ответ
   - «Поставь напоминание» → «я researcher, обратись к ассистенту»

**Главная мысль:** чтобы агент работал как роль, нужно три слоя — **(а) промпт + (б) ограниченные tools + (в) чистая сессия**. Если поменять только промпт — агент продолжит вести себя по-старому.

**ПРИМЕНЕНИЕ К VELA:**

- У нас нет «tools per agent» на уровне платформы (мы делаем агентов через Claude API). Но в `backend/agents.py` каждый агент должен:
  - Иметь чёткую SOUL-секцию в системном промпте: «ты Анна, только остатки/поставки. НЕ берёшь задачи по рекламе, маркетингу, финансам — делегируй Максу».
  - Получать чистый контекст при каждом orchestrate_goal (это и есть «новая сессия»).
- Проверить промпты всех 5 агентов на жёсткие границы. Если в системном промпте размытое описание роли — агент будет лезть в чужие задачи.

## Урок 6 (Модуль 3): Проектирование AI Office для Telegram MiniApp

**Тип:** Теория · 12 мин

**Формула AI Office:**
```
Telegram Mini App = вход
Агенты         = сила
Шаблоны        = подсказки
История        = рабочая память
Ответ          = ценность
```

В первой версии важна **польза, а не красота**. Mini App не должен впечатлять — должен быстро вести к результату.

**Чек-лист проектирования (практическое задание):**
1. Какие агенты внутри?
2. Какую задачу решает каждый?
3. Что пользователь видит на первом экране?
4. Какие шаблоны промптов помогут стартовать?
5. Что точно НЕ делать в первой версии?
6. Какой один сценарий должен работать идеально?

**Главная мысль:** Mini App = оболочка, агенты = ценность. Если убрать оболочку — агенты останутся полезными. Если убрать агентов — пустая оболочка.

- Mini App: есть (`frontend/index.html`)
- 5 агентов: Макс, Лео, Анна, Зара, Ева

- Шаблоны промптов: пока нет — **TODO добавить кнопки-шаблоны** «Покажи продажи», «План поставок», «Что с кампаниями», «Анализ карточки»

## Урок 7 (Модуль 3): Собираем рабочий AI Office Mini App

**Тип:** Практика · 20 мин

**Главная мысль:** не бывает «написал промпт → Codex собрал → всё идеально». Бывает: первая версия → плохо читается в тёмной теме → задача не доходит до агента → нужны особые настройки → агент медленный, как учитывать.

**Архитектурный паттерн — AgentProvider слой:**

Backend НЕ должен вшивать Hermes в `/api/tasks`. Вместо этого — `AgentProvider` интерфейс:
- `MockProvider` — для локальной разработки
- `HermesProvider` — для реального запуска

Backend работает так: «если mock → отвечаем заглушкой. Если real → отправляем в Hermes». Чистая граница, можно собрать UI и backend без агентов, потом подключить.

**Детальный план MVP** (из урока):
- React/Vite Mini App UI: список агентов, описание, шаблоны промптов, textarea, кнопка, ответ, история
- Telegram WebApp SDK: theme params, viewport, initData
- Каждый API request шлёт raw initData в header
- Backend: FastAPI, проверка initData через HMAC, auth_date TTL, allowlist Telegram user IDs
- Каталог агентов + шаблонов
- Records задач: для коротких → ответ сразу, для долгих → status=running, frontend поллит
- Deploy: HTTPS через nginx на VDS, Mini App URL через BotFather menu button
- Bot token только в systemd EnvironmentFile, НЕ в git
- Hardening: rate limits, log redaction, no-secret checks

## Главные принципы, которые я заберу из курса

1. **Tools > промпт** — ограничение инструментов важнее любых инструкций. (Урок 5)
2. **Brief > текст** — агент возвращает структуру с источниками, не свободный текст. (Урок 4)
3. **Постоянный контекст** — voice-guide, swipe-file, banned-phrases важнее любого промпта. (Урок 2)
4. **Infrastructure first** — где файлы, как сохраняются, как защищены секреты — важнее всех агентов. (Урок 3)
5. **Mini App = оболочка** — ценность в агентах, а не в UI. (Урок 6)
6. **AgentProvider слой** — отделяй «как вызывается агент» от «что делает backend». Можно собрать UI до того, как агенты готовы. (Урок 7)
